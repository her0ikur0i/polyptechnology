# Repository audit — 2026-08-09

Scope: whole repository at `f58a649` (CONTRACT-014, pushed to `origin/main`).
Method: direct inspection. Every finding below cites a file and line that was
actually opened; nothing here is inferred from documentation alone. Where a
prior contract already recorded a finding, that is marked `(known)` — the
audit's job was to verify those are still real and to find what they missed.

Host constraint recorded for every recommendation below: **2 vCPU, 7.8 GB RAM,
80 GB free disk, Node 22.23.2.** No recommendation in this audit requires more.

## Findings

### [CRITICAL] Factory Live has no server side at all

`src/dashboard/factory-live/api.ts:5,17` fetches `/api/v1/factory-live/snapshot`
and opens an `EventSource` on `/api/v1/factory-live/events`. Neither route is
registered anywhere in `src/control-api/app.ts` — the server's complete
registered path list contains no `factory-live` entry, and no file outside
`src/dashboard/factory-live/` references the feature at all. The renderer, the
layout engine, the frame-budget controller, the caps, the gap recovery, and the
reduced-motion handling are all real and well built; they have nothing to
render.

The reason no test caught this is that `tests/dashboard/factory-live.test.tsx:6`
imports `liveSnapshot` from a fixture. Every Factory Live test exercises the
client against synthetic data, so the suite is green while the feature cannot
function in the running application.

This also means **release criterion 8 is recorded incorrectly**.
`docs/contracts/CONTRACT-010/acceptance-matrix.md` marks "Factory Live displays
real versioned events and pauses when hidden" as `Verified`, citing
"runtime-validated snapshot/SSE projection, gap recovery, stale/replay state,
visibility/intersection/reduced-motion pause, semantic hierarchy, renderer
tests, and production build pass". Every item in that citation is client-side
and fixture-fed. The pause-when-hidden half of the criterion is genuinely
verified; the "displays real versioned events" half cannot be, because no
component emits them.

**Fix:** build the real producer — a snapshot route and an SSE event route that
project actual orchestration state (work-engine leases, task attempts, gateway
routing decisions, approval waits) into the `LiveNode`/`LiveEdge`/`LiveEvent`
shapes the client already validates, with the same owner auth and scope
filtering as every other route. Correct the acceptance matrix in the same
contract. The client needs no redesign. **Effort:** L.
**Owner:** CONTRACT-017 (its own contract; too large to append elsewhere).

### [HIGH] Dashboard sourcemaps are built and served

`dist-dashboard/assets/index-9XRs13dx.js.map` is 1.47 MB against a 289 KB
bundle, and `src/control-api/app.ts:773` serves the built directory as an SPA.
Anyone who can load the dashboard can read its full original source. Harmless
while staging is loopback-bound; an information-disclosure finding the moment
the public hostname cutover happens.

**Fix:** disable sourcemap emission for production builds in `vite.config.ts`,
or exclude `*.map` from what the Control API serves. **Effort:** S.
**Owner:** CONTRACT-015 M3.

### [HIGH] Three separate path-traversal guards

- `src/worker/planner.ts:4` — `safeWorkerPath()`
- `src/work/git-publication.ts:16` — `safePath()`
- `src/operations/patch-scope.ts:9` — `safePath()`

This is the boundary that stops an AI-authored diff from writing outside its
declared scope, implemented three times independently. A hardening fix applied
to one reaches neither of the others, and the three can drift without any test
noticing. `docs/RESUME.md` recorded this as a two-way duplication; it is
three-way. `(known, understated)`

**Fix:** one module, adversarial tests covering the union of all three
implementations' protections. **Effort:** M. **Owner:** CONTRACT-015 M2.

### [HIGH] No rate limiting anywhere

No match for any rate-limiting implementation or dependency across `src/` and
`package.json`. Every Control API request can reach `AiGateway`, which spends
real money. The budget ledger (`src/gateway/postgres-ledger.ts`) caps spend per
contract scope but does not cap request volume, so an attacker or a runaway
client burns budget and CPU up to the cap. Deferred by CONTRACT-013 M8 as "out
of scope for private staging" — still true today, and still a hard blocker for
public exposure. `(known)`

**Fix:** throttle at the Control API boundary; exempt nothing silently, and
handle the Telegram webhook separately since it authenticates by `secret_token`
rather than owner session. **Effort:** S. **Owner:** CONTRACT-015 M3.

### [HIGH] `src/providers/**` is a competing abstraction with zero importers

No file outside `src/providers/` imports anything from it. It implements a
provider registry, router, and adapter interface — the same responsibility
`src/gateway/**` actually performs in production. The problem is not the dead
bytes; it is that a reader has two plausible answers to "how does this system
route to a provider" and no way to tell which is live. `src/index.ts` and
`src/work/postgres-publication-recorder.ts` are likewise unimported. `(known)`

**Fix:** delete all three; prove by full-suite pass. **Effort:** S.
**Owner:** CONTRACT-015 M1.

### [MEDIUM] The policy canary is not wired to anything

`scripts/policy-canary.ts` has zero references from `src/`. `docs/RESUME.md`
instructs the operator to run it by hand before approving any new
`MODEL_POLICY_VERSION`. A safety check that depends on operator memory is not a
safety check. `(known)`

**Fix:** call it from `PostgresPolicyStore.validate()` so an unproven policy
version fails closed. **Effort:** S. **Owner:** CONTRACT-015 M4.

### [MEDIUM] The dashboard's declared typeface has never loaded

`src/dashboard/styles.css:2` sets `font-family: "DM Sans", system-ui,
sans-serif`. There is no `@font-face`, no stylesheet link, and no font asset
anywhere in the repository. Every user has always seen `system-ui`. The
declared design intent has never once rendered.

**Fix:** load the face or stop naming it — either is honest, the current state
is not. **Effort:** S. **Owner:** CONTRACT-015 M6.

### [MEDIUM] Dashboard API responses are unvalidated

`src/dashboard/api.ts` is 578 lines; `src/dashboard/validation.ts` exports one
function. Most responses reach React through unchecked `as` casts, so a
server-side shape change surfaces as a render crash rather than a handled
error.

**Fix:** validate at the boundary, with a handled error path. **Effort:** M.
**Owner:** CONTRACT-015 M5.

### [MEDIUM] All 11 routes ship in one eager chunk

Zero `lazy()` boundaries in `src/dashboard/app.tsx`; the production bundle is a
single 289 KB JS chunk plus 10 KB CSS. Modest today, but it grows with every
page and there is no boundary to grow against.

**Fix:** route-level code splitting. **Effort:** S. **Owner:** CONTRACT-015 M6.

### [MEDIUM] Docker isolation is never exercised in CI

`src/worker/planner.ts:63-75` implements genuinely strong isolation —
`--read-only`, `--cap-drop=ALL`, `--security-opt`, `--pids-limit`, `--memory`,
`--cpus`, `--network=none`. This is real, not documentation theatre. But
`tests/ai-patch-driver-docker.integration.test.ts:131` skips unless
`dockerAvailable`, and `.github/workflows/quality.yml` never sets
`TEST_WORKER_IMAGE`, so the sandbox that contains AI-authored code is the one
part of the system CI never tests.

**Fix:** run the Docker suite in CI, or state explicitly in the workflow why it
cannot. **Effort:** M. **Owner:** CONTRACT-019 (with multi-stack verification).

### ~~[LOW] Five silent `catch {}` blocks~~ — WITHDRAWN, this finding was wrong

The original claim was that five `catch` blocks discard their error entirely.
**It is false, and the fault was in the audit's own method.** The count came
from `grep -c "catch {}\|catch (_) {}\|catch {$"`, whose third alternative
matches `catch {` at end of line — a parameterless catch, an ordinary
TypeScript idiom — rather than an empty catch _body_.

Re-checked during M3 with a parser-shaped search for `catch (...) { }` with an
empty body across every `.ts` and `.tsx` file under `src/`: **zero matches.**
All eleven parameterless catches in the codebase have real bodies — they throw
(`src/gateway/cli-adapters.ts:103`), return a typed failure
(`src/operations/readiness.ts:22`,
`src/operations/blueprint-translation-driver.ts:118`), `continue`
(`src/operations/execution-supervisor.ts:59`), set component state
(`src/dashboard/policy-control.tsx:207`,
`src/dashboard/conversation-workspace.tsx:459`), or carry an explanatory
comment for a deliberate tolerance
(`src/dashboard/conversation-workspace.tsx:117,292,394`).

Recorded rather than deleted, because an audit that quietly removes its own
mistakes is not one this project's evidence discipline can rely on. M3's scope
shrank accordingly.

### [LOW] Test counts are environment-dependent

`{ skip: databaseUrl === undefined }` and `{ skip: !dockerAvailable }` gate
large portions of the suite. On a machine without `TEST_DATABASE_URL`, the
suite passes while testing very little. CI does set it, so this is a local-
development trap rather than a CI gap — but "178 tests pass" means nothing
without naming the invocation that produced it.

**Fix:** already mitigated by the standing zero-skip invocation in
`docs/RESUME.md`; make the suite report skips loudly instead. **Effort:** S.
**Owner:** CONTRACT-015 M8.

## What the audit found to be genuinely good

Recording these matters as much as the defects, because the next contract must
not "fix" them.

- **Authorization coverage is essentially complete.** Every mutating route in
  `src/control-api/app.ts` carries `requireOwner` and `requireCsrf` except the
  Telegram webhook, which is deliberately authenticated by `secret_token`
  instead and documents that decision inline at line 111.
- **Docker isolation is real**, not aspirational — see the flag list above.
- **Upload limits are real**: 25 MB cap, single file, media-type allowlist
  (`src/control-api/attachment-upload.ts:26,44,46`). The known weakness is that
  the media type is client-declared and therefore spoofable — already recorded
  and deliberately accepted.
- **No provider secret reaches argv.** The CLI adapters shell out without
  credentials on the command line; the DeepSeek adapter passes its key in an
  `authorization` header (`src/gateway/deepseek-adapter.ts:98`). `/proc`
  exposure was specifically checked for and not found.
- **CI is meaningful, not decorative** (`.github/workflows/quality.yml`): it
  applies every migration to a clean pinned Postgres, runs `npm run verify`
  (typecheck, backend tests, dashboard tests, dashboard build), `npm audit`,
  and a secret-pattern scan, with SHA-pinned actions.

## Process observation

`src/` 16,117 lines · `tests/` 7,992 · `docs/` 6,716, across 14 contracts and
24 milestone evidence files. The documentation is not disproportionate in
volume, but the milestone ceremony has become expensive relative to delivered
capability: CONTRACT-014 spent twelve full milestones — including an
independent security review and a staging redeploy — and produced a chat window
that still lacks streaming and markdown rendering.

The recommendation is not to abandon the discipline, which is the reason this
system is auditable at all. It is to scale ceremony to risk: milestones
touching money, secrets, code execution, or approval boundaries keep the full
treatment; milestones that are purely presentational do not need an independent
security review to close.
