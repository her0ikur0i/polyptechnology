## Testable scenarios for the owner to run by hand on staging

1. Open `http://127.0.0.1:4180/` (via the SSH tunnel), click
   "Orchestrator" -- confirm there is no blueprint form anywhere, only a
   "Start a conversation" screen with a title field and a project
   picker.
2. Start a conversation, send a message -- confirm it appears
   immediately in the thread and an "assistant is replying..." state
   shows while the reply task is `queued` (it will stay queued on this
   instance, since the background supervisor is not running by design;
   this proves the request path, not a full generated reply).
3. Send a couple more messages describing a small project idea, then
   use the "Draft proposal" action -- confirm a proposal panel appears
   showing the compiled transcript, with Approve/Reject buttons.
4. Click Approve -- confirm the proposal moves to a handed-off state and
   a "Translate to blueprint" action becomes available. Click it --
   confirm a translation task is queued (again, stays `queued` without
   the supervisor running -- proves the request path).
5. Try uploading a `.png` under 25MB -- confirm it's accepted and listed.
   Try uploading a `.exe` or an oversized file -- confirm both are
   rejected with a clear error, not a blank failure.
6. From the conversation history panel: rename a conversation, archive
   it (confirm it disappears from the default list), toggle "show
   archived" (confirm it reappears), unarchive it, then use the search
   box to filter by a substring of an existing title.
